# ADR% Hottest Stock Screener

A GitHub Actions-powered stock screener that runs nightly after US market close, fetches data from Yahoo Finance across 9 sequential batches, and serves results through a dark-themed browser dashboard deployed on Vercel.

## Universe of Tickers

**File:** `universe.csv`

- A CSV file containing a column named `ticker` or `symbol` (case-insensitive).
- If neither column header exists, it defaults to parsing the first column.
- Blank rows are ignored.
- **Slash Skipping**: Ticker symbols containing a slash `/` (e.g. `BRK/B`, `JPM/PM`) are **skipped** during the split phase to avoid Yahoo Finance query failures.
- There is no hard limit on the number of tickers, and the 9-batch split system supports universes of over ~10,000 symbols comfortably within standard execution limits.

**Example:**

```csv
ticker
AAPL
TSLA
NVDA
AMC
BBIG
```

## Screening Criteria & Logic

All criteria below must be satisfied for a stock to receive a **PASS** status. Each criterion is evaluated independently. If the data field required to evaluate a criterion is `null` / unavailable (`N/A`), **that criterion is skipped** — it does not contribute a failure. A stock only fails if a criterion has valid data and that data does not meet the threshold.

| # | Criterion | Field | Operator | Threshold |
|---|-----------|-------|----------|-----------|
| 1 | Market Cap | `marketCap` | `>` | $25,000,000 |
| 2 | Performance 1 Month | `perf1M` | `>` | 30% |
| 3 | Average Volume 60D | `avgVolume60D` | `>` | 300,000 |
| 4 | Volume (latest session) | `volume` | `>` | 100,000 |
| 5 | Price | `price` | `>=` | $1.00 |
| 6 | Float | `float` | `<=` | 75,000,000 shares |
| 7 | Volatility 1 Week | `volatility1W` | `>` | 3% |
| 8 | Performance 1 Week | `perf1W` | between | -10% and +10% (inclusive) |

> **Market:** US-listed securities only. The ticker universe supplied in `tickers.txt` is assumed to be US-market symbols. No additional country filter is applied programmatically.

## Metric Definitions

### Price
Last closing price (or latest available intraday price) in USD, sourced from `regularMarketPrice` in Yahoo Finance's quote endpoint.

### Market Cap
`marketCap` from Yahoo Finance info. Expressed in USD.

### Float
`floatShares` from Yahoo Finance info. Number of shares available for public trading.

### Average Volume 60D
Mean of daily volume over the trailing 60 trading days, computed from historical OHLCV data. Yahoo Finance returns up to 60 bars when `period="3mo"` with `interval="1d"` is requested; use the last 60 rows.

```
avgVolume60D = mean(history[-60:]["Volume"])
```

### Volume
Most recent session's volume: `regularMarketVolume` from Yahoo Finance quote.

### Relative Volume (RelVol)
Ratio of today's volume to the 60-day average volume. Indicates how unusually active the stock is today.

```
relVol = volume / avgVolume60D
```

### Performance 1 Week (Perf 1W)
Percentage change in closing price from 5 trading days ago to today.

```
perf1W = (price_today - price_5d_ago) / price_5d_ago * 100
```

### Performance 1 Month (Perf 1M)
Percentage change in closing price from 21 trading days ago to today.

```
perf1M = (price_today - price_21d_ago) / price_21d_ago * 100
```

### Performance YTD (Perf YTD)
Percentage change in closing price from the last trading day of the prior calendar year to today.

```
perfYTD = (price_today - price_ytd_start) / price_ytd_start * 100
```

`price_ytd_start` is sourced by fetching the first available close on or after January 1st of the current year using `history(start="YYYY-01-01", end="YYYY-01-10", interval="1d").iloc[0]["Close"]`.

### Volatility 1 Week
Standard deviation of daily returns over the trailing 5 trading days, expressed as a percentage. Daily return = `(Close_t / Close_t-1) - 1`.

```
daily_returns = history[-6:]["Close"].pct_change().dropna()
volatility1W  = std(daily_returns) * 100
```

> Uses population standard deviation (`ddof=1` is acceptable for 5 data points).

### ADR% (14-Day Average Daily Range)
Average of `(High - Low) / Close` over the trailing 14 trading days. Display column only — not used as a filter.

```
adr14 = mean( (High - Low) / Close )  over last 14 bars
```

Expressed as a percentage (multiply by 100 before storing).

## Scripts

### split\_batches.py

**Purpose:** Reads `universe.csv`, parses the ticker/symbol column, then writes 9 evenly-sized batch files to `data/batch_input_N.csv` (N = 0–8). It skips any tickers containing a slash (`/`) in their symbol names.

**Usage:**
```bash
python scripts/split_batches.py
```

**Behaviour:**
- Distributes tickers round-robin across 9 files so batch sizes are as equal as possible.
- Overwrites any existing batch input files.
- Prints a summary: total tickers found and how many went into each batch.
- Exits with code 1 if `universe.csv` is missing or empty.

**Output files:** `data/batch_input_0.csv` … `data/batch_input_8.csv`

---

### fetch\_batch.py

**Purpose:** Reads one batch input file, fetches all required metrics from Yahoo Finance for each ticker, and writes a JSON result file.

**Usage:**
```bash
python scripts/fetch_batch.py --batch 0
# processes data/batch_input_0.txt → data/batch_0.json
```

**Arguments:**

| Argument | Required | Description |
|----------|----------|-------------|
| `--batch` | Yes | Batch index (0–5) |
| `--sleep` | No | Seconds to sleep between tickers on timeout (default: 90) |
| `--retries` | No | Number of retries per ticker on failure (default: 2) |

**Per-ticker fetch logic:**

1. Call `yf.Ticker(symbol).info` to retrieve: `regularMarketPrice`, `marketCap`, `floatShares`, `regularMarketVolume`.
2. Call `yf.Ticker(symbol).history(period="1y", interval="1d")` to retrieve OHLCV history.
3. Compute all derived metrics (avgVolume60D, relVol, perf1W, perf1M, perfYTD, volatility1W, adr14) from the history DataFrame.
4. Evaluate each screening criterion. Store `null` for any metric that cannot be computed. Skip criteria whose metric is `null` when determining PASS/FAIL.
5. Assign `status: "PASS"` or `status: "FAIL"`.

**Timeout / rate-limit handling:**
- If a `yf` call raises an exception (any exception), wait `--sleep` seconds (default 90) then retry up to `--retries` times.
- If all retries are exhausted, write the ticker's entry with all metrics `null` and `status: "N/A"` (treated as neither PASS nor FAIL in the dashboard).
- Log each failure to stderr with the ticker symbol and exception message.

**Output file:** `data/batch_N.json`

```json
[
  {
    "ticker": "AAPL",
    "price": 178.50,
    "marketCap": 2800000000000,
    "float": 15400000000,
    "avgVolume60D": 58000000,
    "volume": 62000000,
    "relVol": 1.07,
    "perf1W": 2.3,
    "perf1M": 8.1,
    "perfYTD": 14.5,
    "volatility1W": 1.2,
    "adr14": 1.8,
    "status": "FAIL",
    "failedCriteria": ["float", "volatility1W"]
  }
]
```

**Fields in each ticker object:**

| Field | Type | Description |
|-------|------|-------------|
| `ticker` | string | Ticker symbol |
| `price` | number \| null | Latest close price (USD) |
| `marketCap` | number \| null | Market capitalisation (USD) |
| `float` | number \| null | Float shares |
| `avgVolume60D` | number \| null | 60-day average daily volume |
| `volume` | number \| null | Latest session volume |
| `relVol` | number \| null | Relative volume (volume / avgVolume60D) |
| `perf1W` | number \| null | 1-week performance (%) |
| `perf1M` | number \| null | 1-month performance (%) |
| `perfYTD` | number \| null | Year-to-date performance (%) |
| `volatility1W` | number \| null | 1-week volatility (%) |
| `adr14` | number \| null | 14-day ADR% |
| `status` | string | `"PASS"`, `"FAIL"`, or `"N/A"` |
| `failedCriteria` | string[] | List of criterion keys that caused a FAIL (empty if PASS) |

### merge\_results.py

**Purpose:** Reads all 9 `data/batch_N.json` files and merges them into a single consolidated `frontend/output/results.json`. It also writes run metadata to `frontend/output/meta.json` and registers the run date in `frontend/output/runs.json`. Date-specific logs `results_<date>.json` and `meta_<date>.json` are generated in the same directory.

**Usage:**
```bash
python scripts/merge_results.py
```

**Output — `frontend/output/results.json`:**
A flat JSON array of all ticker objects from all batches, in ticker-alphabetical order.

**Output — `frontend/output/meta.json`:**
```json
{
  "runDate": "2025-01-15",
  "runTimestampUTC": "2025-01-15T21:05:33Z",
  "totalTickers": 500,
  "passCount": 12,
  "failCount": 481,
  "naCount": 7
}
```

## GitHub Actions Workflows

We use two distinct GitHub Actions workflows to coordinate universe splitting and nightly stock screening.

### 1. Split Universe (Ad-hoc)

**File:** `.github/workflows/split_universe.yml`

#### Trigger
- **On Push:** Triggers when modifications are pushed to `universe.csv`.
- **Manual:** `workflow_dispatch` — allows running manually via the GitHub Actions tab.

#### Steps
1. Checkout repository
2. Set up Python 3.11
3. Run `split_batches.py` to regenerate `data/batch_input_N.csv` files (N = 0–8).
4. Commit and push batch input files back to the repository.

---

### 2. Nightly Screener Run

**File:** `.github/workflows/screener.yml`

#### Trigger
- **Schedule:** `cron: '0 21 * * 1-5'` — runs at 21:00 UTC Monday–Friday (approximately 5 PM ET, one hour after market close).
- **Manual:** `workflow_dispatch` — allows on-demand runs from the GitHub Actions UI.

#### Steps
1. Checkout repository
2. Set up Python 3.11
3. Install dependencies (`pip install -r requirements.txt`)
4. Run `fetch_batch.py --batch 0`
5. Run `fetch_batch.py --batch 1`
6. Run `fetch_batch.py --batch 2`
7. Run `fetch_batch.py --batch 3`
8. Run `fetch_batch.py --batch 4`
9. Run `fetch_batch.py --batch 5`
10. Run `fetch_batch.py --batch 6`
11. Run `fetch_batch.py --batch 7`
12. Run `fetch_batch.py --batch 8`
13. Run `merge_results.py`
14. Commit and push updated results and metadata files inside the `data/` directory to the main branch.

> **Note:** Steps 4–12 run **sequentially** (not in parallel) to stay within Yahoo Finance's rate limits. Each `fetch_batch.py` call has its own 90-second sleep safety valve on timeout.

#### Commit message
```
chore: update screener results [YYYY-MM-DD]
```

The commits are made using the `GITHUB_TOKEN` secret that is automatically available in all GitHub Actions environments. No additional secrets are required.

### requirements.txt
```

pandas>=2.0.0
numpy>=1.24.0
requests>=2.31.0
```

## Browser App — index.html

A single self-contained HTML file located in `frontend/index.html`. No build step. No framework. Pure HTML + CSS + vanilla JavaScript.

### Data Loading
On page load, the app fetches `./output/runs.json` to populate the selectable run dates. It then fetches `./output/results.json` and `./output/meta.json` by default (representing the latest run).

If the user selects a specific date from the dropdown, the app queries `./output/results_<date>.json` and `./output/meta_<date>.json`. If a specific date query fails, it automatically falls back to fetching the latest data.

```
fetch('./output/runs.json')
fetch('./output/results.json') // or results_<date>.json
fetch('./output/meta.json')    // or meta_<date>.json
```

### Default State
- **Filter:** PASS only (toggle button to show all stocks).
- **Sort:** Relative Volume descending.
- **Column sorting:** Click any column header to sort ascending/descending (toggle).

### UI Sections

#### Header Bar
- App title: **ADR% Hottest Stock Screener**
- Last run date and time (from `meta.json`)
- Counts: `X PASS · Y FAIL · Z N/A · Total: N`
- Toggle button: **Show PASS only / Show All**

#### Filter Toggle
When "Show All" is active, the grid displays every ticker from the universe with a colour-coded status badge:
- `PASS` — green badge
- `FAIL` — red badge
- `N/A` — grey badge (data unavailable)

When "Show PASS only" is active, only `PASS` rows are displayed.

## CSV Export Behaviour

Two export buttons appear above the grid, always visible regardless of the active filter:

### Export: Tickers Only
Downloads a `.csv` file containing a single column — `ticker` — for every row **currently visible** in the grid (respects the PASS/All toggle).

```
ticker
NVDA
SMCI
ASTS
```

**Filename:** `hottest_stocks_tickers_YYYY-MM-DD.csv`

### Export: All Fields
Downloads a `.csv` file with all columns for every row currently visible in the grid.

**Filename:** `hottest_stocks_full_YYYY-MM-DD.csv`

**Column order in CSV:**
`ticker, price, marketCap, float, avgVolume60D, volume, relVol, perf1W, perf1M, perfYTD, volatility1W, adr14, status`

Numeric values are exported raw (unformatted), e.g. `marketCap` as `2800000000` not `$2.8B`. `null` values are exported as empty strings.

## Vercel Deployment

**File:** `vercel.json`

```json
{
  "version": 2,
  "builds": [
    { "src": "index.html", "use": "@vercel/static" },
    { "src": "data/**", "use": "@vercel/static" }
  ],
  "routes": [
    { "src": "/(.*)", "dest": "/$1" }
  ]
}
```

### Deployment steps
1. Push the repository to GitHub.
2. Connect the repository to a new Vercel project (Framework Preset: **Other**).
3. No build command. Output directory: `/` (root).
4. Deploy. Vercel will serve `index.html` and `data/results.json` statically.

### Keeping results fresh
Every time the GitHub Action commits updated `data/results.json` to the `main` branch, Vercel automatically triggers a redeployment (if the Vercel GitHub integration is enabled). The updated results are live within ~30 seconds of the commit.

> **Tip:** To avoid triggering a full Vercel redeployment on every nightly data commit (which counts against deployment limits), you can alternatively configure `index.html` to fetch `results.json` from the raw GitHub URL:
> ```
> https://raw.githubusercontent.com/<owner>/<repo>/main/data/results.json
> ```
> This means the HTML file never needs to change — only the data file does.

## PASS / FAIL Logic

```
PASS  = all criteria with available (non-null) data are satisfied
FAIL  = at least one criterion has available data that does not meet the threshold
N/A   = all metric fields are null (data fetch failed entirely for this ticker)
```

### Pseudocode

```python
def evaluate(ticker_data):
    criteria = [
        ("marketCap",    lambda v: v > 25_000_000),
        ("perf1M",       lambda v: v > 30),
        ("avgVolume60D", lambda v: v > 300_000),
        ("volume",       lambda v: v > 100_000),
        ("price",        lambda v: v >= 1.0),
        ("float",        lambda v: v <= 75_000_000),
        ("volatility1W", lambda v: v > 3),
        ("perf1W",       lambda v: -10 <= v <= 10),
    ]

    failed = []
    all_null = True

    for field, check in criteria:
        value = ticker_data.get(field)
        if value is None:
            continue          # skip — N/A for this field
        all_null = False
        if not check(value):
            failed.append(field)

    if all_null:
        return "N/A", []
    elif failed:
        return "FAIL", failed
    else:
        return "PASS", []
```
